## Summary

This change builds the first InsForge OAuth auth slice, adds protected route shells, and sets up Vitest plus Playwright tests. The structure is mostly clear, and the tests trace the auth acceptance criteria well. Two contract issues block merge: unauthenticated users can remain stuck on protected pages instead of being sent to login, and raw auth errors are logged to the browser console.

## Blockers

### 🔴 Protected pages can hang instead of redirecting, `components/auth/ProtectedPage.tsx:37`

**Problem**: `ProtectedPage` waits on `activeClient.auth.getCurrentUser()` with no timeout or fallback. The Playwright test at `e2e/auth.spec.ts:23` proves `/dashboard` stays on `/dashboard` in the “Opening your workspace” state instead of reaching `/login` for an unauthenticated browser.

**Why it matters**: This violates AC-3 in `docs/specs/0001-insforge-oauth-auth.md:28`. The protected content is not shown, which is good, but the user is left on a dead protected route instead of being sent to sign in.

**Suggested fix**: Make the guard deterministic. Ensure `getCurrentUser()` always resolves for the unauthenticated path, or wrap it in a short timeout that treats no settled session as unauthenticated and routes to `/login`. Keep the protected content hidden until the session is confirmed.

### 🔴 Raw OAuth errors are exposed in browser logs, `components/auth/AuthPanel.tsx:94`

**Problem**: OAuth start failures call `console.error("[auth/oauth]", error)`, passing the raw error object through to browser logs. The new test at `components/auth/AuthPanel.test.tsx:107` fails because a secret shaped message is logged even though the UI shows safe copy.

**Why it matters**: This violates AC-5 in `docs/specs/0001-insforge-oauth-auth.md:30`, which requires readable feedback without exposing raw secrets. Browser console logs are user visible and can be captured by support tooling or extensions.

**Suggested fix**: Log only a safe diagnostic code or a sanitized summary for expected auth failures. If deeper raw diagnostics are needed, keep them server side where secrets are controlled, not in the browser console.
